## ToolEntry
* 目的：让进入tool系统的每一个tool都是一个标准格式的对象，方便之后调用. ttt做
* 主要参数：
```aiignore
name                      工具名，LLM 调用时使用 -> str
toolset                   所属工具集（如 "terminal", "web", "file"） -> str
schema                    OpenAI 格式的 JSON Schema 字典 -> dict
handler                   工具处理函数，接收 (args_dict,**kwargs)  -> callable
check_fn                  可用性检测函数，返回 bool ->callable
requires_env              需要的环境变量列表 -> list
is_async                  是否为异步处理器 -> bool
```

## ToolRegistry
* 目的：存储所有工具的元数据         ttt做，稍微有点难度
* 主要参数
```aiignore
_tools                    存工具名 -> 元数据   -> dict
_toolset_checks           存工具集名 -> 可用性检测函数   -> dict
_toolset_aliases          存别名 -> 规范名        -> dict
_lock                     可重入锁，通过threading.RLock()创建
```

* 主要函数
1. _snapshot_state() -> 返回一个_tools的快照，返回的是一个元组，(ToolEntry,Callable)
2. _evaluate_toolset_check() -> 检查这个toolset_check是否可用,接收参数为tool_set和check,最后返回一个bool值，代表是否可用
3. register() -> 创建ToolEntry放入
4. deregister() -> 从registry中删除一个tool，接收参数为name
5. get_defination() -> 返回一个openai格式的schema，接收参数为tool_names，返回list[dict]
6. dispatch() -> 执行所指定的tool,并返回一个json格式的字符串     我来做

# 编排层：model_tools.py      ttt量力而为
作用：负责暴露tool内部的各个modules，并给应用层调用
1. handle_function_call() -> 先对args进行清理，然后判断是不是tool_search，如果是就调用tool_search系列的方法
                             如果不是，那就继续往下执行，最终交给registry的dispatch方法来执行最后的工具调用
2. _get_tool_loop() -> 存储全局变量_tool_loop，判断是否存在，存在就直接返回，不存在就获取，通过asyncio.new_event_loop()来调用
3. get_worker_loop() -> 获取当前工作的线程
4. _run_async() -> 先检查目前是否已在event_loop中 -> 在，创建一个一次性线程
                   然后在loop中跑任务，跑完之后将loop中的所有任务取消，最后再关闭线程,这个交给我做
